# RAG\-Chatchat\-Rerank

## 项目简介

本项目基于开源主流知识库问答框架 **LangChain\-Chatchat** 进行二次开发，构建一套本地化私有文档 RAG 问答系统。原生框架仅采用「向量相似度粗排」进行文档检索，存在召回精度低、易引入无关上下文、大模型容易产生幻觉等问题。

本项目**核心优化**：在原生向量检索链路基础上，新增 **BGE\-Reranker 重排模块**，实现「向量粗排 \+ 模型精排」的工业级双阶段检索架构，显著提升知识库问答准确率，降低大模型幻觉。

可用于 PDF / Markdown 等私有文档知识库搭建、企业内网知识问答、大模型私有领域落地等场景。

## 技术栈

- **后端框架**：Python、FastAPI、LangChain

- **向量检索**：FAISS、BGE\-Embedding

- **检索优化**：BGE\-Reranker（交叉编码器精排）

- **大模型能力**：LLM API 对话、Prompt 工程

- **业务能力**：文档解析、文本分块、知识库管理、上下文问答

## 系统架构与流程

### 优化前（原生单阶段 RAG）

文档解析 → 文本分块 → Embedding 向量化入库 → 向量相似度召回 → Prompt 拼接 → LLM 回答

**缺陷**：向量相似度仅为浅层语义匹配，容易召回语义不相关、关键词相似的噪声片段，诱发幻觉。

### 优化后（本项目双阶段 RAG）

文档解析 → 文本分块 → Embedding 入库 → **向量粗排召回 Top6** → **Rerank 精排过滤 Top3** → Prompt 组装 → LLM 生成答案

**核心改进**：增加精排环节，对粗排候选做细粒度语义相关性打分，严格过滤低质量上下文。

### 整体系统架构图

**架构说明**

1\. 知识库构建：文档解析、切片、向量化存入FAISS；

2\. 推理阶段：用户问题先做向量检索粗排，一次性召回6个候选chunk；

3\. 核心改动：新增Rerank交叉编码器模块，对Query\+每一段文档做联合语义打分；

4\. 根据相关性分数过滤，只保留Top3最相关片段送入大模型，减少无关上下文，降低幻觉。

## Rerank 重排模块实现原理（项目核心亮点）

### 1\. 粗排与精排的区别

- **向量粗排（Embedding）**：双塔结构，Query 和文档分别编码，计算向量空间相似度。速度极快，适合全库筛选，但精度有限。

- **Rerank 精排（Cross\-Encoder）**：将「Query \+ 文档片段」拼接输入模型，Token 之间完全交叉 Attention，直接输出 0\~1 相关性分数。语义判断精准，但推理成本更高，仅适合少量候选打分。

### 2\. 本项目实现策略

- 向量检索阶段：召回 **Top6** 候选片段，保证候选多样性；

- 重排阶段：使用 **BAAI/bge\-reranker\-base** 对所有候选打分；

- 过滤策略：设置分数阈值 **0\.01**，丢弃低相关噪声；

- 最终筛选：保留相关性最高 **Top3** 片段送入 LLM；

- 模型全局单例加载，避免重复加载导致推理卡顿。

### 3\. 优化收益

- 大幅减少无关上下文进入 Prompt，有效降低大模型幻觉；

- 问答精准度、上下文相关性显著提升；

- 贴合工业级 RAG「粗排海量筛选 \+ 精排精准提纯」的标准架构。

### 4\. 方案局限性（面试加分思考）

- Rerank 为串行推理，会小幅增加问答耗时；

- 受模型 512 上下文限制，超长文本片段会被截断；

- 纯向量\+重排无法解决关键词精准匹配缺失问题，可后续叠加 BM25 多路召回。

## 本地部署教程


## 开发踩坑记录

- **问题1**：模型循环加载，问答延迟极高
       
**解决**：将 Rerank/Torch 模型改为全局单例加载，只初始化一次。
      

- **问题2**：长 Chunk 文本超出模型 512 长度限制
       
**解决**：限制分块大小，控制输入长度，避免无效截断丢失信息。
      

- **问题3**：阈值过低导致噪声多、过高召回过少
        
**解决**：经过多轮测试确定 0\.01 为最优平衡阈值。
