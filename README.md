# RAG\-Chatchat\-Rerank

## 项目简介

本项目基于开源主流知识库问答框架 **LangChain\-Chatchat** 进行二次开发，构建一套本地化私有文档 RAG 问答系统。原生框架仅采用「向量相似度粗排」进行文档检索，存在召回精度低、易引入无关上下文、大模型容易产生幻觉等问题。

本项目**核心优化**：在原生向量检索链路基础上，新增 **BGE\-Reranker 重排模块**，实现「向量粗排 \+ 模型精排」的工业级双阶段检索架构，显著提升知识库问答准确率，降低大模型幻觉。

可用于 PDF / Markdown 等私有文档知识库搭建、企业内网知识问答、大模型私有领域落地等场景。

## 技术栈

- **后端框架**：Python、FastAPI、LangChain

- **向量检索**：FAISS、BGE\-Embedding

- **检索优化**：BGE\-Reranker（交叉编码器精排）

- **大模型能力**：LLM API 对话、Prompt 工程

- **业务能力**：文档解析、文本分块、知识库管理、上下文问答

## 系统架构与流程

### 优化前（原生单阶段 RAG）

文档解析 → 文本分块 → Embedding 向量化入库 → 向量相似度召回 → Prompt 拼接 → LLM 回答

**缺陷**：向量相似度仅为浅层语义匹配，容易召回语义不相关、关键词相似的噪声片段，诱发幻觉。

### 优化后（本项目双阶段 RAG）

文档解析 → 文本分块 → Embedding 入库 → **向量粗排召回 Top6** → **Rerank 精排过滤 Top3** → Prompt 组装 → LLM 生成答案

**核心改进**：增加精排环节，对粗排候选做细粒度语义相关性打分，严格过滤低质量上下文。

### 整体系统架构图

**架构说明**

1\. 知识库构建：文档解析、切片、向量化存入FAISS；

2\. 推理阶段：用户问题先做向量检索粗排，一次性召回6个候选chunk；

3\. 核心改动：新增Rerank交叉编码器模块，对Query\+每一段文档做联合语义打分；

4\. 根据相关性分数过滤，只保留Top3最相关片段送入大模型，减少无关上下文，降低幻觉。

## Rerank 重排模块实现原理（项目核心亮点）

### 1\. 粗排与精排的区别

- **向量粗排（Embedding）**：双塔结构，Query 和文档分别编码，计算向量空间相似度。速度极快，适合全库筛选，但精度有限。

- **Rerank 精排（Cross\-Encoder）**：将「Query \+ 文档片段」拼接输入模型，Token 之间完全交叉 Attention，直接输出 0\~1 相关性分数。语义判断精准，但推理成本更高，仅适合少量候选打分。

### 2\. 本项目实现策略

- 向量检索阶段：使用 `VECTOR_SEARCH_TOP_K` 召回候选片段，保证候选多样性；

- 重排阶段：使用 **BAAI/bge\-reranker\-base**（CrossEncoder）对「Query + 每个候选片段」联合打分；

- 过滤策略：按相关性分数排序，只保留 `RERANKER_TOP_N`（默认 3）个最相关片段送入 LLM；

- 模型全局单例懒加载，仅在首次开启重排时加载一次，避免重复加载导致推理卡顿；

- **重排可通过 `USE_RERANKER` 配置项自主开关**，默认关闭，不影响原生检索链路。

> 详细改动文件、配置项与效果对比方法见 [docs/RERANK_IMPLEMENTATION.md](./docs/RERANK_IMPLEMENTATION.md)。

### 3\. 优化收益

- 大幅减少无关上下文进入 Prompt，有效降低大模型幻觉；

- 问答精准度、上下文相关性显著提升；

- 贴合工业级 RAG「粗排海量筛选 \+ 精排精准提纯」的标准架构。

### 4\. 方案局限性（面试加分思考）

- Rerank 为串行推理，会小幅增加问答耗时；

- 受模型 512 上下文限制，超长文本片段会被截断；

- 纯向量\+重排无法解决关键词精准匹配缺失问题，可后续叠加 BM25 多路召回。

## 本地部署教程

### 1\. 环境依赖

Python \>= 3\.9

```bash
pip install -r requirements.txt
pip install transformers torch sentence-transformers
```

### 2\. 模型下载

自动在线拉取：`BAAI/bge-embedding-base`、`BAAI/bge-reranker-base`

### 3\. 启动项目

```bash
python startup.py
```

访问本地 Web 页面，上传文档构建知识库，即可开启 RAG 问答。

## 项目核心改动点

基于原生 Chatchat 最小侵入式改造，共改动 3 个文件：

- **`chatchat/settings.py`**：在 `KBSettings` 中新增 `USE_RERANKER` 等 Rerank 配置项，支持开关与模型参数；
- **`chatchat/server/knowledge_base/kb_service/base.py`**：新增 `get_reranker()` 全局单例懒加载函数；在所有向量库共用的检索入口 `KBService.search_docs()` 中，向量粗排召回后、返回前注入 CrossEncoder 重排，重排失败自动回退原始结果；
- **`libs/chatchat-server/pyproject.toml`**：声明 `sentence-transformers` 依赖。

改动遵循「默认关闭、按需开启」原则：关闭时不加载模型、完全不影响原有流程；开启后才对召回结果做精排过滤。

## 开发踩坑记录

- **问题1**：模型循环加载，问答延迟极高
       
**解决**：将 Rerank/Torch 模型改为全局单例加载，只初始化一次。
      

- **问题2**：长 Chunk 文本超出模型 512 长度限制
       
**解决**：限制分块大小，控制输入长度，避免无效截断丢失信息。
      

- **问题3**：`RERANKER_TOP_N` 与向量召回 `VECTOR_SEARCH_TOP_K` 数量不匹配
        
**解决**：重排候选数应小于等于向量召回数，经多轮测试将 `RERANKER_TOP_N` 设为 3，在精度与速度间取得平衡。
